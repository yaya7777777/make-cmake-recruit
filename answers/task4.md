# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

核心区别是make是**增量编译**
- build.sh：通常是无脑执行，每次运行脚本，它都会把所有的源文件重新编译一遍，即使只改了一个文件，它也会从头开始，耗时较长
- Make：更加聪明，Make会根据Makefile中定义的依赖关系，检查源文件和目标文件的时间戳，只有当源文件时间戳比目标文件新（即源文件被修改过）时，它才会重新编译该文件，这大大节省了编译时间

## 2. CMake 是编译器吗？执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

**CMake不是编译器**
- CMake是一个构建系统生成器，它本身不具备编译代码的能力
- 当执行 cmake --build build 时，CMake实际上是在读取build目录下由它自己之前生成的构建文件（Windows系统下通常是Makefile或Visual Studio工程文件），然后调用底层的原生构建工具
- 所以最终真正在干活的是底层的构建工具（如make）去调用编译器（如gcc或cl.exe）来完成C源文件的编译和链接

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

- 节省时间，提高开发效率：在大型项目中，源文件可能成百上千个，编译一个大型项目可能需要几分钟甚至几十分钟，如果只改了其中一个文件，却要重新编译所有文件，开发效率会极其低下

- 避免不必要的资源消耗：重新编译所有文件会消耗大量的CPU和内存资源，通过增量编译（只重新编译修改过的文件），可以让开发过程更加流畅
